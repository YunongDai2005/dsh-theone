# 产品指标

TheOne 当前处于工程收敛阶段：暂停新功能，所有改动以是否改善下列数字为评判标准。每个指标都有可操作的统计口径，确保两个人测量能得到相同的结果。

## 主要指标

| # | 指标 | 定义 | 方向 |
| --- | --- | --- | --- |
| 1 | **路由准确率** | 正确目标是*已有话题*的消息中，被正确路由到该话题（KEEP / MOUNT / SWAP 指向正确 context）的比例 | 越高越好 |
| 2 | **误分率** | 被路由到*已有话题*的消息中，落错话题的比例。（与新建话题无关——那是指标 3 的范畴。） | 越低越好 |
| 3 | **任务拆分率** | 两个错误方向，分开统计：**过度拆分** = 同一进行中任务的消息新建了话题而非继续；**过度合并** = 无关消息被留在了不属于它的话题里。以全部路由决策为分母 | 越低越好 |
| 4 | **内存增长** | 固定回放负载下 Host 进程 RSS 增量（基线运行 vs. +N 条消息），以及每个话题的 SQLite 目录库大小。分别在后台索引开启与关闭时测量 | 越平越好 |
| 5 | **恢复成功率** | 运行中途杀掉/重启 DSH 后：工作会话、挂载状态和 `lastState` 完整保留、且下一条消息能正确继续的话题比例 | 越高越好 |

## 测量方法

- **1–3：回放基准。** 把现有回放工具（历史上的 AI Box 回放，人工目录下 75/79）扩展为可重复脚本：`fixtures/` 负载 → 路由决策 → 与人工标注答案比对打分。每个版本在同一组 fixture 上出分，保证跨版本可比。基准使用 mock 模型，不消耗 API 配额。
- **4：增长探针。** 一个测试按话题回放 N 条消息，固定间隔采样 RSS，增长超出记录预算即失败。目录库大小按话题行断言。
- **5：混沌测试。** 在每个检查点（路由中、worker 启动中、回复中、回复后）打断运行并验证恢复行为的测试：`store.interruptTopicRuns()` 已是实现切入点。

## 验收门槛

- 改善一个指标的改动不得隐性恶化另一个（例如收紧新建话题的阈值降低了过度拆分，但抬高了误分率）。
- 回放得分和增长预算按版本记录在本文件的变更历史里，而不是提交说明里。
- 这五个指标之外的数字不阻塞发版。

## 当前状态

- 基线回放得分：人工目录下 75/79（见 [v0.1 验收报告](./plugin-v0.1.zh.md)）。这是单一数据集上的一次运行，不是统计上强的基线。
- 增长探针与混沌测试：尚未实现。在它们落地之前，指标 4 每版人工复核，指标 5 仅由现有会话恢复测试覆盖。

# 计划表（持续执行）

每次继续工作前先读这份文件，按顺序做下一项；做完一项就在这里打勾并提交。

## 目标：设计语言

TheOne 的最终设计：**一个入口，用户只说话，其余无感。**

1. **一个入口。** 用户只在主聊天里说话，不用挑会话、挑话题、挑文件夹。
2. **只说话。** 大部分操作中，用户在当前会话里输入和选择，就结束了。不让用户做影响体验的选择；拿不准时用安全的默认值，而不是去问用户。只有真正要用户决定的事（授权、AI 提出的选项）才在主聊天里弹出来，选完自动继续。
3. **无感。** 整理、分话题、并行处理、合并回复都在后台进行。主聊天读起来始终是一段普通对话：一问一答，按发送顺序。
4. **只整理，不改动。** 只做用户端、前端的整理，后台不改。用户自己的会话、设置、文件夹不被改写。
5. **装前关后没有区别。** 关掉或卸载 TheOne，DSH 和安装前一样；再打开，一切回来。
6. **和原生能力一致。** 话题里能做的事和普通 DSH 会话一样多（工具、命令、插件、面板），不少一样。

每项改动都先用这六条检查一遍；做不到的，写进「需要讨论」，不自己改结构。

## 执行规则

- 结构性的大改动：先写方案放到 `docs/`，等用户确认，不先改代码。
- 只测有风险的地方；默认关闭的功能（Linker 等）保持关闭。
- 每次推送前跑 `npm run typecheck`（含测试的完整类型检查，CI 用的就是它）和 `npm test`；发版后确认 npm 上确实是新版本。
- 以用户身份提交（YunongDai2005），推到 main；攒够一批改动就写 release notes 发版（自动发 npm）。
- 不要求用户粘贴任何 API Key 或 Token。
- 回复用户用中文。

# 待确认的方案

这些改动会改变结构，按计划表的规则先写方案，等确认再动手。每一项都按设计语言检查过：一个入口、用户只说话、无感、只整理不改动、装前关后没有区别。

## 1. 主聊天记录越来越大

**现状。** 主聊天把每个话题的回复、思考、工具调用和结果都存了一份副本（这样才能像普通会话一样显示）。它的增长速度是所有话题加起来的总和。DSH 的自动压缩只缩小发给模型的上下文，不缩小这份记录。用上几个月，记录可能有几百 MB，DSH 打开主聊天、滚动、搜索都会变慢。话题自己的会话不受影响，它们保留完整记录。

**方案：主聊天分「章」。**

- 主聊天的记录超过一个阈值（建议原始大小 30 MB，或 1000 轮）后，在下一次你发消息之前，TheOne 悄悄开一个新的主聊天会话接着用。你在侧边栏点的还是同一个「TheOne · 主聊天」，当前话题、模型和权限都照旧。
- 新的一章开头有一行提示：「更早的对话在 话题工作区 → 以前的主聊天」。旧的那一章放进 DSH 的归档（和 TheOne 其他会话一样），可以随时打开看，不会删。
- 关掉 TheOne 时，所有章节一起归档；再打开时恢复最新的一章。
- 话题会话不受影响，每件事的完整历史都还在话题里。

**另一个可以一起做的小改动：** 单个工具结果超过 64 KB 时（比如很长的日志输出），主聊天里只存前 64 KB，后面加一句「完整输出在话题『X』里」。卡片照常显示，只是太长的部分不再复制一份。

**需要你决定：**

1. 阈值：30 MB / 1000 轮可以吗？
2. 以前的章节放在「话题工作区 → 以前的主聊天」，还是只放在 DSH 的归档里？
3. 长工具结果截断要不要做？

## 2. 拆分话题

**现状。** 一个话题聊着聊着变成了两件事（比如「京都旅行」里混进了签证材料），目前只能用「分错了」一条一条挪，或者在话题目录里手动合并、删除，没有拆分。

**方案：说一句就拆。**

- 你在主聊天里说「把签证的事单独拆出来」（任何说法都行，由路由模型判断，不靠关键词）。
- TheOne 新建话题「签证」：从原话题复制一份完整上下文（和「分支」一样），并告诉它「从现在起只负责签证这件事」；原话题记一句「签证的事已经拆到『签证』」。两边各自的摘要会随后台整理更新。
- 之后关于签证的消息自动去新话题。原话题的历史不删、不改。
- 主聊天里只出现一行提示「＋ 签证（从 京都旅行 拆出）」，不需要你确认。

**需要你决定：**

1. 拆出来的新话题带原话题的完整上下文（像分支，多花一些 token，但什么都不丢），还是只带一份摘要（更省，但细节可能丢）？
2. 要不要也支持反过来的「把 A 和 B 合成一件事」？（话题目录里已经有手动合并。）

## 3. 主聊天里看不到话题的子代理和用量

- 原生会话顶部有「N 个子智能体」，可以点开查看子代理；主聊天没有，因为子代理挂在话题会话名下。
- 原生会话底部有用量和上下文占比；主聊天没有。可以显示当前话题的，但 DSH 判断要不要自动压缩主聊天时也看这份数据，显示话题的用量可能让主聊天被提前压缩。

**需要你决定：** 这两项要不要做。要做的话，第一项需要让主聊天能列出当前话题的子代理（改会话之间的父子关系），第二项需要先确认 DSH 的压缩逻辑不会被误触发。

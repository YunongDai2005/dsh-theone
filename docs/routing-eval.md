# 路由修准：评测与改动（2026-10-18 ~ 19）

后端计划第 ③ 步。目标：减少「一件事被拆成多个话题」，不让其他指标变差。代码在 `claude/epic-hawking-xzrmak`，未合并、未发布。

## 结论

- **插件实际的路由设置（关掉思考）准确率是 90.1%（open）/ 92.9%（closed），不是 README 写的 86.6% / 91.6%。** README 的数字来自更早的代码。本次复测时发现评测代理默认开着思考（开思考是 96.5% / 99.4%），和插件路由时关思考的设置不一致，所以全部改成关思考重测。
- **最有效的改动是「再判断一次」**：快速判断（关思考）要新建话题、要追问用户，或和线索冲突时，开着思考再问一次。
  - open 模式：90.1% → **96.3%**；closed 模式：92.9% → **98.7%**；测试集（调参时没用过）open 模式：90.7% → **97.1%**。基本追平全程开思考。
  - 「一件事拆成几个话题」1.80 → 1.47，无谓追问 49 → 9 次。
  - 只有 9%（closed）到 18%（open）的消息触发；每 1000 条消息成本 $0.41 → $0.49（全程开思考 $0.55）；没触发的消息延迟不变。
- **「证据」交给快速判断没用，已撤回**：第一版连普通词也当线索，把消息引到了错的话题；改成只用数字、编号、名字后仍然略差。现在证据只用来触发「再判断一次」。
- **剩下的主要问题**：「放错到别的话题」2.8%（全程开思考 1.5%），来自没触发复核的快速判断（留在当前话题 24 例、切到另一个话题 18 例）。

## 评测方法

- 数据：InterleaveBench `interleave-v0`。开发集 40 段对话、1971 条消息；测试集 10 段、495 条（调参时没用过）。一个人在同一个对话框里同时推进 3–5 件事，中英文各半。每条消息属于哪件事由生成前的剧本决定；另一个模型不看剧本独立读一遍，读法不一致的标为有歧义，不计分（开发集计分 1631 条）。
- 方式：逐条消息交给插件自己的路由代码（提示词、输入格式、校验、复核都从 `dist/` 调用）。open 模式从零开始、话题由路由自己创建，算分时把它建的话题和真实的几件事一一配对；closed 模式事先给好话题列表。
- 模型：`deepseek-v4.1-flash`，经 OpenAI 兼容代理；关思考用 `reasoning_effort: "none"`，和插件路由时请求 `off` 一致。
- 置信度：按对话为单位重复抽样（同一段对话里的错误会连锁），给 95% 区间；两组比较用配对抽样，并数「变好 / 变差」的对话段数。每组只跑了一次，模型本身有随机性。
- 局限：数据是合成的，没有助手回复；open 模式里话题的「当前状态」用最后一条消息代替（插件里是话题自己写的状态）。适合比较改法好坏，不等于真实使用中的准确率。

复现：

```sh
export OPENAI_BASE_URL=… OPENAI_API_KEY=… EVAL_EXTRA_BODY='{"reasoning_effort":"none"}' EVAL_RPM=28 EVAL_CONCURRENCY=24
node eval/run-router.mjs --mode open --policy theone --model deepseek-v4.1-flash --recheck   # 去掉 --recheck 是现状
python3 eval/score.py eval/data/interleave-v0/sessions.jsonl eval/data/interleave-v0/predictions/*.jsonl
```

## 结果

### open 模式（从零开始建话题），开发集

| 组 | 准确率（95% 区间） | 话题/件事 | 放错到别的话题 | 追问 | 复核比例 | 每 1000 条 |
|---|---|---|---|---|---|---|
| 关思考，只用 LLM（插件现状） | 90.1%（87.9–92.2） | 1.80 | 2.4% | 49 | – | $0.41 |
| + 证据（含普通词）+ 冲突复核 | 90.8% | 1.79 | **3.3%** | 48 | 1.7% | $0.41 |
| **+ 再判断一次（新建/追问/冲突）** | **96.3%（94.2–97.8）** | **1.47** | 2.8% | 9 | 18.2% | $0.49 |
| + 再判断一次 + 证据（只用数字/编号/名字） | 95.9% | 1.52 | 3.0% | 9 | 17.4% | $0.49 |
| 参照：全程开思考 | 96.5%（94.3–98.3） | 1.33 | 1.5% | 9 | – | $0.55 |

配对比较：
- 再判断一次 vs 现状：准确率 +6.1（+4.7～+7.6），33 段变好、1 段变差；放错 +0.4（不显著）。
- 再判断一次 vs 全程开思考：准确率 −0.25（不显著）；放错 +1.35（显著）。
- 第一版证据 vs 现状：准确率 +0.7（不显著）；放错 +0.9（显著，11 段变差、3 段变好）。
- 再判断一次加上强线索证据 vs 只加再判断一次：准确率 −0.37（0 段变好、4 段变差）。

「再判断一次」改动的 108 次判断：追问→已有话题 29 次（24 次对）；新建→已有话题 78 次（58 次对，15 次把一次性的换算/算术问题放进了相关话题，如「22 篇离 30 篇还差几篇」进了开题报告，危害很小；真正放错的 4 次）。

### 测试集 closed 模式

再判断一次：97.1%（95.1–98.8），复核 8.5%，每 1000 条 $0.45。关思考基线见下方补充。

## Token 与延迟

每条消息的路由（按 V4.1 Flash 高峰价：输入 $0.30、缓存命中 $0.006、输出 $1.20 每百万 token；开发集 open 模式）：

| 组 | 调用/条 | 输入 token/条（缓存命中） | 输出 token/条 | 每 1000 条 |
|---|---|---|---|---|
| 关思考 | 1.00 | 1661（37%） | 73 | $0.41 |
| + 再判断一次 | 1.18 | 1928（46%） | 141 | $0.49 |
| 全程开思考 | 1.00 | 1658（41%） | 209 | $0.55 |

延迟（一条条单独请求、不排队，经代理，绝对值偏慢）：关思考中位数 4.7 秒，开思考 7.3 秒。触发再判断的消息要多等一次开思考的调用（合计约 12 秒），其余消息不变。

## 插件里改了什么

- `src/routing-evidence.ts`（新）：
  - 线索：消息里的数字（3 位以上）、编号、名字，到每个话题收到过的消息（`route_details` 摘录）、目录信息和卡片里查，只在一个话题出现过的才算。
  - `secondLook`：快速判断为新建话题、追问，或和唯一一个持有线索的话题冲突时，开着思考再问一次（`recheck`）；第二次调用失败则保留第一次的判断。
- `src/llm-router.ts`：`recheck` 进入路由输入（附 `RECHECK_PROMPT`）；`decide(…, { think })` 第二次调用不关思考。快速判断的输入和以前一样。
- `src/topic-memory.ts`：卡片新增「已定」（关键数值和决定，最多 6 条，只留最新值），第 4 次回复后每 8 次回复重写一次。和再判断一次一起时，放错的比例有下降趋势（见上）。
- 评测：`--recheck`、`--cards`，`EVAL_RPM` 节流，卡片 token 记录。

## 调研（GitHub / 论文）摘要

- 对话解缠研究（Kummerfeld 2019 等）：「最近性」是最强信号（88% 的回复指向 8 条以内的消息）；可给话题加「隔了几条消息」特征，或让模型输出「这句在接最近哪一条」。
- 语义路由（semantic-router）、bge-m3 混合检索：可作为候选预筛和软证据。本次实验说明，把线索直接交给快速判断帮助不大，更值得用在「是否需要再看一次」上。
- 记忆系统（mem0、Letta、Graphiti、MemOS 等）都不负责判断消息属于哪条线；DSH 社区的记忆插件（dsh-mnemon 月下载 4.6 万、OpenViking 3.9 万等）是给干活的模型用的，不能直接用于路由。DSH 原生只有 AGENTS.md 和会话全文索引（FTS5）。
- 可靠性技巧：logprob 置信度（DSH 接口目前拿不到）、多次投票（限速下太慢）、话题干活时退回分错的消息、新话题先临时建（要改交互）。

## 建议

1. **上线「再判断一次」**（已在分支上）。三组数据（开发集 open、closed，测试集 open）都是 +6 个百分点左右，几乎没有对话段变差，成本增加约 20%，延迟只落在新建话题、追问和冲突的消息上。
2. 发版时把 README 的数字换成本次关思考 + 再判断一次的结果，并注明模型、注明数据是合成的。
3. 新卡片一起上线：放错的比例 2.8% → 1.9%（接近显著），代价是每 1000 条消息多约 $0.16。
4. 「放错到别的话题」仍是下一步重点：可以做成「更仔细的路由」选项（切换话题时也再判断一次，复核比例约 45%），或者试调研里的「隔了几条消息」特征。
5. 用户装了 dsh-mnemon 这类自动回忆插件时，要验证它不会把一个话题的记忆带进另一个话题。

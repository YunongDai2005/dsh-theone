# 话题会话的显示与归档

设置页第一组「会话显示」中的「隐藏话题会话」默认关闭。它控制通过主聊天发起的话题会话是否显示在 DSH 侧边栏，保存后生效。主聊天本身仍使用专用入口，普通 DSH 会话不受此开关影响。

## 行为边界

- 关闭隐藏：话题会话正常显示，插件恢复自己收起的会话，不自动归档新的话题会话。
- 开启隐藏：侧栏过滤话题行；空闲且未置顶的话题会话可自动归档，下一次执行前恢复。
- 用户置顶的话题仅通过侧栏过滤隐藏，不自动归档。DSH 的归档操作会清除置顶，因此插件关闭、重新开启及切换显示设置都要保留这些置顶。
- 用户手动归档的会话不因保存显示设置而恢复。自动归档失败不能留下会导致误恢复的归档记录。
- 兼容旧版：首次升级时，旧版没有记录归档来源的自有话题会话会被一次性纳入恢复记录；之后使用持久化记录区分自动归档。普通 DSH 会话不参与这次迁移。

## 并发与生命周期

- 同一会话已有归档操作时不重复提交。恢复显示或准备下一轮执行时，先等待该操作结束。
- 快速关闭、开启、再关闭隐藏时，不得提前清除尚未落盘的归档记录。
- 插件关闭时清理重试定时器，等待正在进行的归档结束，再关闭数据库；异步查询晚返回时不再访问已关闭的数据库。
- 侧栏只采纳最新请求的结果；已失效或卸载后的响应不更新界面。会话 ID 发生替换时也刷新，即使总数没变。
- 同源窗口通过设置版本号通知重新读取服务端状态，不把会话内容或设置内容写入浏览器存储；窗口重新获得焦点时也会刷新。

## 验证

`tests/session-visibility.test.ts` 覆盖延迟归档、快速切换、执行前恢复、归档失败、关闭期间的晚返回，以及真实 DSH 工作区存储下的持续对话、重启、手动归档和置顶保护。

`tests/client-session-visibility.test.ts` 覆盖乱序响应、主入口与话题行的区别、离线状态和卸载后的响应。

2026-10-29 在独立 DSH 网页实例中，用固定回复模型完成了从主聊天发起话题、默认侧栏显示、开启隐藏、关闭后双窗口恢复的界面验证。没有使用外部模型，也没有修改用户日常使用的 DSH 配置。这不等同于桌面端实测或发布验证。

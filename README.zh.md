*节选自 TheOne 宣传片（夜间版）。*

用户始终在一个主聊天入口里聊天。TheOne 判断所属项目，挂载项目摘要，再交给该项目独立的 DSH Worker 执行。DSH 保存原始对话、运行模型与工具；TheOne 保存项目目录、摘要和路由记录。

左侧固定 **TheOne · 主聊天**：浅色主题为淡橙色外光晕，深色主题为淡蓝色。兼容 DSH `0.2.0-rc.2`、Node.js 24。主聊天作为全局入口，不挂到任何项目工作区，也不显示在普通会话列表中。升级时自动解除旧主聊天的工作区关联，保留原始聊天记录。新的主聊天使用 DSH 数据目录中的独立目录；历史话题的文件执行目录保留。

## 安装并使用

1. 先在 DSH 中配置好 API，并选择一个能正常聊天的模型。
2. 打开 **插件 → 添加插件**，粘贴 `https://github.com/YunongDai2005/dsh-theone`，点击安装。
3. 点击左侧 **TheOne · 主聊天**，直接开始聊天。

**v0.3.7 默认开启 LLM 路由，复用 DSH 的模型调用和 API 凭据，无需再填一个 API Key。** 默认情况下，路由、项目 Worker 和入口上下文容量使用打开 TheOne 前 DSH 选中的模型。改模型时，先在 DSH 选好新的普通聊天模型，再打开 TheOne。

仓库公开，包含编译后的后端和 Web 客户端，安装不需要本机编译或安装脚本。也可以用 DSH CLI：

```sh
dsh plugin --profile web add github:YunongDai2005/dsh-theone --ignore-scripts
```

DSH 当前没有插件自动更新；旧版用户按 DSH 插件页提示卸载后重新安装。升级后若默认模型已是 `theone/gateway`，先在 DSH 选择一次已配置的普通模型，再打开 TheOne。插件记住模型名称，重启后继续复用；凭据仍由 DSH 管理。

数据库默认保存在 `$DSH_HOME/theone/contexts.db`，未设置 DSH_HOME 时为 `~/.dsh/theone/contexts.db`。卸载重装应保留这个目录以继续原话题。每个数据库同时运行一个 profile 进程。

界面支持英语和简体中文，随 DSH 当前语言即时切换。DSH 未手动指定语言时，使用其系统 / 浏览器语言设置。切换语言不会创建新主聊天；历史话题的标题、摘要和原始对话保留原语言。

## 设置与入口交互

右键固定的 TheOne 按钮，选择 **设置**。页面列出 14 项运行配置，其中 11 项可通过下拉框和输入框修改；数据库位置、人工目录文件和入口标识暂时只读。

**保存设置** 会把可编辑选项保存到现有 TheOne 数据库，重启 DSH 后生效。已保存的选项会覆盖对应的部署默认值。页面显示未保存的修改和待重启状态；**撤销修改** 恢复上次保存的表单。多个页面同时修改时，旧版本保存会被拒绝，避免覆盖新配置。API 凭据仍由 DSH 或指定的环境变量管理，设置接口不会返回密钥值。

模型下拉框目前提供已知的当前模型和 **跟随 DSH**，暂未列出完整服务商目录。若要跟随另一个 DSH 模型，保持固定服务商和固定模型为空，在 DSH 选择该模型后再打开 TheOne。

主聊天打开时，入口里的淡光晕跟随鼠标移动：白天橙色、夜间淡蓝色，移出按钮后淡出。

## 历史目录与话题工作区

启用后，插件在后台通过 `ctx.sessionQuery` 读取既有 DSH 会话，自动提取话题目录。优先使用已成功完成的 compaction 摘要；没有摘要的部分只读取有界的用户输入和回答摘录。每批最多 8 轮，通过用户在 DSH 配置的模型做轻量提取；不重新总结完整长会话。

相似、相关的话题自动归入同一个 **话题工作区**，在左侧入口中查看。不同话题仍有独立的工作会话，可以点击“继续聊天”回到主聊天，或点击“查看原会话”打开原始 DSH 记录。

话题工作区是插件保存的逻辑分组。DSH 原生工作区绑定磁盘目录，这个版本保留原来的文件执行目录，不把旧会话挪到新目录。历史导入保存摘要和原始事件范围；继续某个历史话题时使用独立 Worker，按需读取来源，不把整个混合会话灌入执行历史。

目录、分组、来源范围和索引进度保存在现有 TheOne SQLite 数据库；原始聊天仍由 DSH 保存。启动时后台整理，聊天结束后增量更新，并定期补扫；没有变化的会话不重复调用模型。每轮扫描最多 64 个提取批次，未完成的内容后续继续处理。历史多时首次整理需要时间并会消耗已配置 API 的额度。

路由结合 DSH 全文搜索召回最多 16 个候选，再交给 LLM 判断。全文搜索失败时改用已有目录；判断为新事项时最多再复查 3 批剩余目录。没有可信匹配、也没有明确依赖旧聊天时，默认开新话题，整理未完成或检索故障也不会因此拦住独立问题。陌生人名、不知道某个事实、人物可能重名，由聊天模型处理，不构成“是不是旧话题”的追问理由。路由只对缺失的历史指代（如“用之前的链接”），或至少两个确实相关旧话题之间难以选择的情况追问。后一种须由分类模型列出相关目录 ID；缺少历史依据的澄清会转为新话题。历史指代检测覆盖常见中英文表达，其他表达仍可能漏判。所选模型支持关闭深度思考时，路由请求会关闭，以免短小的分类输出额度被思考耗尽；主聊天仍使用 DSH 原来的模型设置。候选漏召回也可能创建重复话题，不代表已检索整个历史库。明确以“新话题：”要求创建时仍可创建。

关闭自动目录可设置 `THEONE_HISTORY_CATALOG=false`。已有目录和分组保留。失败会话会显示在整理状态中并在后续扫描重试；单个坏来源不会阻止其他来源。

## 入口上下文与按使用情况压缩

入口直接读取 DSH 所选模型的上下文容量和默认输出额度，包括 adapter 的配置覆盖，不另设固定容量。何时压缩、替换哪段旧内容、保留多少近期原文，仍由 DSH 按原来的容量阈值处理。

DSH 通过 TheOne provider 压缩入口时，插件根据话题目录和已完成的路由调用生成有界摘要：

- **高优先级：**当前话题、一天内用过的话题，或七天内用过且近 30 天至少成功调用三次的话题。保留较长摘要，空间允许时保留最近三组用户输入和回复。
- **一般优先级：**其他近 30 天用过的话题。保留较短摘要，空间允许时保留最近一组对话。
- **低优先级：**更久未用或尚无 TheOne 调用记录的话题。只保留简短摘要和状态，移除对话摘录。重新调用后，它会成为当前话题并恢复优先保留。

频率只计算成功调用，失败与澄清不增加频率；入口重建后仍保留使用记录。压缩摘要会脱敏，并根据模型容量和压缩输出额度限制长度，重复压缩不会重复堆积摘录。生成摘要不额外调用模型，也不启动 Worker 或执行工具。原始 DSH 日志、来源范围、话题摘要和工作会话继续保留，可按需检索。

该规则用于入口的压缩摘要，Worker 继续使用 DSH 原有压缩。规则在 DSH 压缩时生效，不会仅因话题变旧而启动后台压缩任务。若在 DSH 显式配置了另外的摘要 provider，则使用该 provider 的摘要策略。

## 主聊天与普通会话一致

Worker 的每一步都随生成在主聊天中显示为一个原生步骤：思考从第一个字起就在原位置显示，然后是回答文字，工具调用以 DSH 原生工具卡片显示并带有结果。主聊天不会再次执行这些工具：卡片直接使用 Worker 的执行结果，并跳过钩子和权限策略，每个工具只在 Worker 中执行一次。需要授权的工具在主聊天对应卡片上请求审批；Worker 向用户提问（`ask_user_question`）也在主聊天回答。Worker 的待办清单同样显示在主聊天。

Worker 重试某一步时，主聊天按原生重试方式重做这一次尝试，只保留成功的回答。回答期间插话的消息在 Worker 下一步生效，并显示在两步之间；排队的消息在本轮结束后单独路由。取消会停止 Worker。回复字符上限按每一步计算，包含思考；多步任务不会因总长度被中断。如果模型接口一次性返回整段回答，就没有中间文字可供显示。

主聊天里的控件对 Worker 生效。后台模型支持图片时，主聊天也能发送图片，并提供该模型的思考强度选项，所选强度用于 Worker。在主聊天的模型选择器中换成其他模型，Worker 就使用该模型，主聊天仍经由 TheOne 路由；重新选回 TheOne 则跟随 DSH 选中的模型。每次回答前，Worker 采用主聊天的权限模式（沙盒与审批策略一起）；不对应任何预设的手动组合不会复制。

主聊天只显示工具调用而不执行，依靠 TheOne 把自己的处理放在 DSH 工具流程的最前面。如果其他插件也插到它们之前，可能会看到主聊天的镜像调用；作为保险，凡是不对应 Worker 调用的工具调用，主聊天一律拒绝，不会执行。

## 当前功能

- LLM 选择已有话题、新话题或澄清；代码校验目标，并计算 `KEEP / MOUNT / SWAP / CREATE / CLARIFY`。
- 每个项目有一个独立、可恢复的 DSH Working Session；切回项目时继续该 Worker。
- 路由通过 `ctx.llm.prepareCall()` 调用已配置的 DSH provider。只发送短目录、本轮输入和最多 12 条近期文字，不带工具或完整历史。
- 路由每轮额外调用一次模型，会使用用户已有 API 的额度；最大输出 2048 tokens，30 秒超时。它与正式回答分开调用。复查旧目录的几次调用并行进行，新话题约等两次调用的时间。已有话题时，“好的”“继续”“为什么”这类简短承接直接继续当前话题，不调用路由。
- 失败、无效 JSON、未知话题 ID、截断或取消均不会直接切换项目或启动 Worker。权限/限流错误、连续三次其他错误会暂停路由 60 秒。
- Worker 的 `theone_search_history` 按需检索自己专用的 Worker 和人工审核的历史事件范围；最多 10 个窗口、8000 字符摘录。
- `theone_update_state` 保存最多 800 字符的项目进展。自动复用 Worker 完成的 DSH compaction 摘要，脱敏后最多 1200 字符，不重新总结整个会话。
- SQLite 保存目录、来源范围、挂载和执行状态；原始输入、工具结果与回答保存在 DSH 日志。历史指令仅作为参考。
- 主聊天同时接受一个运行中的请求。回答期间的插话交给 Worker，留在当前话题；排队的消息在回答结束后路由。取消传给路由和 Worker，不自动重放执行中的输入。

## 配置（可选）

正常安装不需要这些变量。

| 变量 | 用途 / 默认值 |
| --- | --- |
| `THEONE_HISTORY_CATALOG` | 默认开启；`false` 关闭后台目录整理 |
| `THEONE_DATABASE_PATH` | 覆盖默认目录数据库位置 |
| `THEONE_CONTEXTS_PATH` | 人工目录 JSON；省略时从空目录开始 |
| `THEONE_GATEWAY_KEY` | 入口标识，默认 `default` |
| `THEONE_ROUTER_MODE` | `llm`（默认）或 `rules` |
| `THEONE_ROUTER_TRANSPORT` | `dsh`（默认）；`legacy` 为旧的直接 DeepSeek 调用 |
| `THEONE_WORKER_PROVIDER` / `THEONE_WORKER_MODEL` | 固定模型覆盖，必须一起设置；默认跟随 DSH 选择 |

旧的直接路由仅在 `THEONE_ROUTER_TRANSPORT=legacy` 时使用 `THEONE_ROUTER_API_KEY`、`THEONE_ROUTER_BASE_URL` 和 `THEONE_ROUTER_MODEL`。默认不读取这把 key。

人工目录为 `ContextDescriptor[]`：`id / title / summary / entities / keywords / lastState`，只在首次初始化插入。Worker 不能使用 `theone` provider。

## 开发和测试

```sh
git clone https://github.com/YunongDai2005/dsh-theone.git
cd dsh-theone
npm ci --ignore-scripts
npm run typecheck
npm test
npm run pack:plugin
```

测试使用真实 DSH 服务、AgentLoop、Session、SQLite Query、JSONL 持久化和 compaction；模型被模拟，不调用外部 API。演示目录为虚构资料。

打包生成 `.dsh-test/dsh-theone-0.3.7.tgz`，包含后端、Web 客户端和配置，不包含 API Key、聊天快照或数据库。

本地隔离开发可运行 `npm run install:local` 和 `npm run start:local`，数据保存在 `~/.dsh-theone`。这是独立 profile，需要在其 DSH 设置中配置模型。可复制 `.env.example` 为 `.env` 调整端口等；`.env` 不提交到 GitHub。

## 服务接口

`ctx.theone.searchHistoryDetailed(contextId, query, limit)` 返回审核范围内的窗口、文本投影、来源错误码和 `partial` 标记；`searchHistory()` 只返回窗口。

手工关联的历史 Session 必须通过 `store.addSource(contextId, sessionId, {startSeq, endSeq})` 指定审核后的闭区间。自动目录使用模型分类后经校验的完整轮次范围。专用 Worker 才可关联整段 Session。

## 已知边界

- 主聊天身份保存在当前浏览器、当前 Web 路径的本地存储中；另一个浏览器可能创建另一个 Gateway，同一数据库继续复用项目 Worker。
- 目前面向文字入口，回答文字随 Worker 生成流式显示。Worker 的步骤、工具卡片、审批和提问都显示在主聊天；图片输出尚未转发。
- 没有 embedding 或向量检索；当前候选召回使用短目录和 DSH 全文搜索，主题提取与关联分组由 LLM 判断。MULTI-MOUNT 和 Worker 自动轮换尚未实现。
- 目录更新和 DSH 日志不是跨数据库事务；中断后状态不明的请求需要检查原 Session。未验证硬断电恢复。
- 目录整理需读取 DSH 日志；未进行大规模吞吐验证。历史工具按审核范围扫描来源；Gateway 日志轮换待实现。

早期人工目录下 AI Box 回放为 75/79，不能代表新用户线上准确率。TheOne 尚未部署到 AI Box。旧版本验收见 [v0.1](./docs/plugin-v0.1.zh.md) 和 [v0.2](./docs/plugin-v0.2.zh.md)。

# TheOne：DSH 会话路由插件

[English](./README.md) | 简体中文

> 非官方社区项目，由社区成员独立维护，与 DeepSeek 不存在隶属或背书关系。

<p align="center"><img src="docs/images/theone-film-preview.webp" alt="TheOne 宣传片：One 按钮化作 3D 钥匙，把每条消息路由到对应的会话" width="100%"></p>

*节选自 TheOne 宣传片（夜间版）。*

在 DSH 里只用一个主聊天。TheOne 判断每条消息属于哪件事，交给这件事专属的后台会话（Worker）去做，再把过程原样显示回主聊天。用起来就是一个普通会话，但每个话题的上下文互不干扰，相关的话题又能互相参考。

![TheOne 主聊天与话题工作区](https://raw.githubusercontent.com/YunongDai2005/dsh-theone/main/docs/images/theone-topic-workspaces-en.png)

*截图使用独立 DSH profile 和虚构话题示例。*

兼容 DSH `0.2.0-rc.2` 和 Node.js 24；界面支持简体中文和英语，跟随 DSH 的语言。

## 安装

1. 在 DSH 中配置好 API，选一个能正常聊天的模型。
2. 打开 **插件 → 添加插件**，粘贴 `https://github.com/YunongDai2005/dsh-theone`，点击安装。
3. 点击左侧 **TheOne · 主聊天**，开始聊天。

不需要另填 API Key：路由和后台都复用 DSH 的模型与凭据。命令行安装：`dsh plugin --profile web add github:YunongDai2005/dsh-theone --ignore-scripts`。DSH 暂无插件自动更新，升级时卸载后重装即可；数据在 `$DSH_HOME/theone/contexts.db`（默认 `~/.dsh/theone/`），保留它就能继续原来的话题。

## 和普通会话一样

- 后台的每一步都原样显示在主聊天：思考从第一个字起就在原位置，然后是回答、工具卡片和结果。工具只在后台执行一次。
- 需要授权的工具在对应卡片上审批；后台向你提问，也在主聊天里回答；待办清单同步显示。
- 后台重试时，主聊天像原生会话一样整段重来；回答过程中插话，后台在下一步就会收到。
- 主聊天的控件对后台生效：发送图片（后台模型支持时）、思考强度、权限模式。在主聊天的模型选择器里换模型，就是给后台换模型。
- 「好的」「继续」这类短句直接接着当前话题，不需要等待判断。

## 话题怎么分配

每条新消息先判断：接着当前话题、回到某个旧话题，还是开一个新话题。

- 默认用你在 DSH 选的模型做一次简短分类（关闭深度思考，最多 2048 token，30 秒超时），并结合 DSH 全文搜索从目录中召回候选。没有可信匹配就开新话题，不会追问「是不是新话题」。
- 一句话同时用到几个话题（比如「把 Qwen 的测试结果写进论文」）时，交给实际做事的话题，其余作为参考一起带上，不再反问。
- 只有明确引用了找不到的旧聊天，或确实分不清你指的是哪一个时才会追问。
- 只发图片或文件、没有文字时，接着当前话题。分类调用失败时改用规则判断，拿不准就留在当前话题。
- 分错了？直接说「分错了，是论文的」，上一条会交给正确的话题重新处理；也可以在话题目录的**最近的话题分配**里改。TheOne 会记住这次更正，之后类似的消息分到那里。
- 规则模式（`THEONE_ROUTER_MODE=rules`）不调用模型。

## 话题联动

相关的话题会自动共享进展，范围在设置里选择：

| 联动范围 | 行为 |
| --- | --- |
| 自动学习（默认） | 先根据同一话题工作区、同一项目目录、提到相同的事物判断相关；之后从使用中学习：短时间内来回切换、同时被提到、后台主动查阅都会增强关联，长期不用会逐渐减弱。 |
| 仅同一工作区 | 只在自动分组的话题工作区内联动。 |
| 关闭 | 话题之间不共享任何内容。 |

后台开工时会收到一份参考简报，没有新内容时不发：

- 刚切换话题时，附上主聊天最近几轮对话，「把刚才那个……」这类说法能接上；
- 相关话题自上次以来的变化：最近一次压缩摘要（注明截至时间），以及之后记录的进度；
- 各话题的约束（例如「预算数字只用于采购」）原样附上，并且每次都重新附带，不会因为压缩而丢失。

简报明确标注为参考资料而不是指令。需要细节时，后台可以用 `theone_read_topic` 查看相关话题，或用 `theone_search_history` 搜索它的记录。

在话题目录里可以看到每个话题关联了哪些话题、为什么关联，并且可以手动关联、解除关联（以后不再自动关联）、标记「不共享」，或清空学到的关联。手动设置始终优先。

## 话题目录

TheOne 会在后台读取你已有的 DSH 会话，整理出话题目录，并把相关话题归入**话题工作区**（左侧入口查看）。它优先复用 DSH 的压缩摘要，没有变化的会话不会重复处理。历史较多时，第一次整理需要一些时间和 API 额度。设置 `THEONE_HISTORY_CATALOG=false` 可以关闭。

话题卡片会显示最新进展和约束。点 **管理** 可以重命名、修改摘要和约束、移到其他工作区、合并到另一个话题、把已有的 DSH 会话关联为可检索的历史，或删除话题（原会话仍在 DSH，目录不会再把它整理回来）。**＋ 新话题** 可以手动新建。**最近的话题分配** 列出每条消息分到了哪里、原因、所用模型和耗时。

## 设置

右键左侧的 TheOne 按钮，选择 **设置**。保存后立即生效，只有历史整理相关的设置需要重启 DSH。

| 设置 | 说明 |
| --- | --- |
| 话题提示 | 主聊天里怎样显示话题切换：隐藏、仅切换时显示一行（默认）、每条都显示并注明原因 |
| 联动范围 | 自动学习（默认）、仅同一工作区、关闭 |
| 模型 | 跟随 DSH（默认），或从 DSH 已配置的全部模型中固定后台模型；固定的设置优先于主聊天里的选择 |
| 路由方式 | LLM 判断（默认）或规则判断 |
| 历史整理 | 开关与补扫间隔 |
| 内容限制 | 话题资料长度；后台每一步回复的长度（含思考） |
| 人工话题目录文件 | 可选的 JSON 话题目录，保存时导入 |

数据库位置和主入口标识会让 TheOne 换用另一份数据，所以只能用环境变量 `THEONE_DATABASE_PATH`、`THEONE_GATEWAY_KEY` 设置。另外可选：`THEONE_CONTEXTS_PATH`，以及须一起设置的 `THEONE_WORKER_PROVIDER` / `THEONE_WORKER_MODEL`。

## 数据与隐私

- 原始对话和工具结果由 DSH 保存；TheOne 只在自己的 SQLite 数据库里保存目录、摘要、关联和路由记录。
- 发给路由和写进参考简报的内容会去掉 API Key、密码等敏感信息。
- 标记为「不共享」的话题，不会出现在其他话题的简报、最近对话和查阅结果里。
- 主聊天变长时，DSH 通过 TheOne 压缩它：常用话题保留较长摘要和最近几轮对话，不常用的只保留简短状态。这一步不额外调用模型。

## 已知限制

- 同一时间只处理一个请求；回答期间排队的消息要等本轮结束后再处理。
- 新话题的文件默认写在 `~/.dsh/theone/gateway`，暂时不能给新话题指定项目目录。
- 主聊天里保存了工具调用的副本，长期使用记录会变大；入口日志轮换尚未实现。
- 主聊天身份按浏览器保存：换浏览器或在桌面端会出现另一个主聊天，话题仍然共用。同一个数据库同时只应由一个 DSH 进程使用。
- 图片输出尚未转发；没有向量检索；暂不支持拆分话题。
- 主聊天里的工具卡片只显示、不执行，这依赖 TheOne 位于 DSH 工具流程的最前面。如果其他插件也抢到最前面，可能会看到这些镜像调用，但工具不会执行两次。

## 开发

```sh
git clone https://github.com/YunongDai2005/dsh-theone.git
cd dsh-theone
npm ci --ignore-scripts
npm run typecheck
npm test
```

测试使用真实的 DSH 运行时（AgentLoop、Session、SQLite、JSONL 持久化、压缩），只模拟模型，不调用外部 API。`npm run pack:plugin` 生成安装包；`npm run install:local` 和 `npm run start:local` 会在 `~/.dsh-theone` 启动一个独立的 DSH profile。

服务接口：`ctx.theone.searchHistoryDetailed(contextId, query, limit)` 检索话题的已审核历史；`store.addSource(contextId, sessionId, { startSeq, endSeq })` 关联会话的一部分。旧版本验收记录见 [v0.1](./docs/plugin-v0.1.zh.md) 和 [v0.2](./docs/plugin-v0.2.zh.md)。
